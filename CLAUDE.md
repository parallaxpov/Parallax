# Правила заполнения мер ГОСТ Р 57580.1 — рабочий документ ВИКИ

Золотой стандарт (эталонные меры): КЗИ.3, КЗИ.5, КЗИ.6, КЗИ.9, КЗИ.10, КЗИ.11, ИУ.4, ЖЦ.2, ЖЦ.4, СЗИ.3, КЗИ.4.
При любой неуверенности в структуре или формулировке — сверяться в первую очередь с ними.

## Столбец D — Пояснение

1. Первое предложение всегда начинается с «Суть меры заключается в…» и раскрывает формулировку меры своими словами (не пересказ, а разъяснение).
2. Если у меры несколько компонентов (в названии есть дефисы, перечисление, «включающий:») — разбить на нумерованный список, по пункту на компонент.
3. Финальный абзац всегда начинается с «Главная цель меры — …» и объясняет, зачем мера нужна — часто через контраст: что произойдёт, если она выполняется формально или не выполняется вовсе.

## Столбец E — Реализация

4. Структура строго по коду вида меры. Подраздел создаётся только для букв, отличных от **Н**:
   - код О-Т-Т → подразделы «Реализация - О» и «Реализация - Т»
   - код Н-Т-Т → только «Реализация - Т»
   - код О-О-О → только «Реализация - О»
5. Заголовок каждого подраздела («Реализация - О», «Реализация - Т») выделяется **жирным**.
6. Каждый подраздел открывается рамочной фразой:
   - «Организационная реализация предполагает…»
   - «Техническая реализация предполагает…»
   - «Поскольку мера реализуется только техническими методами, её внедрение предполагает…»
7. Далее — нумерованный список конкретных шагов/направлений реализации.
8. **Мера закрывается только в соответствии со своим типом.** Техническая часть не может быть закрыта организационными мерами, и наоборот — организационная часть не может подменяться технической. На практике оба варианта возможны, но при проверке регулятором мера не будет засчитана как реализованная без части, соответствующей её типу. Явно это не проговаривать в тексте меры, но следить, чтобы «Реализация - О» содержала только организационные шаги, а «Реализация - Т» — только технические.
9. Для технической части — при упоминании средств защиты:
   - сначала называется **класс средства** в общем виде (антивирус, межсетевой экран, SIEM, СКЗИ и т.д.);
   - затем — пустая строка;
   - затем примеры конкретных продуктов **по трём категориям**: зарубежные, российские сертифицированные (по перечню ФСТЭК — см. отдельно предоставленную базу), решения с открытым исходным кодом.
10. Техническую часть, где применимо, закрывать перечнем конкретных полей для фиксации: «Для каждой операции должны фиксироваться как минимум: дата и время, идентификатор…, результат…».

## Столбец F — Проверочные процедуры (свидетельства)

11. Та же структура подразделов «- О» / «- Т», что и в Реализации, заголовки также **жирным**.
12. Только конкретные названия артефактов, которые реально запросит аудитор (регламент, акт, журнал, отчёт СЗИ/SIEM, итоги интервью) — без обобщений вида «документация».

## Столбец G — Типичные недостатки

13. Нумерованный список, 3–6 пунктов.
14. Каждый пункт — конкретный, проверяемый сценарий нарушения (не абстрактный риск). Частые паттерны: «от случая к случаю», «не все объекты», «не документируется», «хранится меньше установленного срока».

## Столбец H — Комментарий / ToDo

15. Обязательное поле для случаев неуверенности при AI-заполнении: если недостаточно информации для точного ответа по конкретной мере (устаревшие данные, нестандартная инфраструктура, спорная трактовка) — фиксировать это здесь явно, не выдавая предположение за факт.

## Общее форматирование

16. Внутри списков пункты разделяются «;», последний пункт — «.».
17. Пустая строка между подразделами «- О» и «- Т».
18. Пустая строка между описанием шагов реализации и примерами СЗИ (класс → пример).
19. Длина не нормируется искусственно — объём определяется сложностью конкретной меры.
20. **Сокращения** (ПО, СЗИ, НСД и т.д.) расшифровываются при первом употреблении **в рамках каждой отдельной меры**: «программное обеспечение (ПО)» → далее в этой же мере только «ПО». При переходе к следующей мере расшифровка нужна заново при первом использовании — пользователь открывает конкретную меру точечно, а не читает документ подряд.
