# PARALLAX — план сайта

Живой документ: что задумано, что сделано, что отложено. Обновлять по ходу работы.

## Концепция

Сайт состоит из двух слоёв.

- **Верхушка — портфолио.** Для работодателей и заказчиков: кто я, проекты, навыки, публикации.
- **Логово (`#lair`) — личное место.** Не для посетителей, а для себя: самовыражение,
  проекты, идеи, видение, записи и логи. Цель — через время перечитывать и сравнивать,
  копить материал для будущих проектов. Дух личных сайтов 20–30-летней давности, но
  по-настоящему живой и интерактивный. Сайт должен быть интересным, даже если его
  никто не посещает.

Принцип: противостоять упрощённому, скучному дизайну большинства интерфейсов.
Интерактивность и «живость» важнее минимализма.

## Сделано

- Вход в логово: скрытая точка в футере → трещина (клик 1) → искра, зарядка,
  белая вспышка из центра трещины (клик 2).
- Секция «Контакты» и футер разлетаются на осколки; под ними открывается слой
  логова с собственным фоном (`--den-bg`, розовая точечная сетка).
- Контакты после взрыва переезжают в шторку, которую открывает «Контакты» в навигации.
- Плавный спуск к `#lair` (`lair.js`).
- Пост наблюдения в `#lair` (WATCH ROOM · «пост наблюдения»): три CCTV-камеры с
  картинками (`assets/lair/feed-*.webp`), живыми часами, REC, помехами и редкими
  сбоями сигнала (`lair.js`).

## Пост наблюдения и комнаты

Логово — это пост охраны (**WATCH ROOM — «Пост наблюдения»**) с мониторами
видеонаблюдения. Каждый монитор показывает, что происходит в одной из «комнат».
Сам пост и есть ИБ-часть логова: зритель сидит в комнате охраны. Отдельной
«комнаты хакера» нет.

Комнаты (утверждено):
1. **SECTOR 0x01 — BLIND SPOT** — лаборатория исследований: ИБ, ИИ, психология;
   исследования, гипотезы, заметки. «Слепая зона» — то, что другие предпочитают не замечать.
2. **SECTOR 0x02 — WORKSHOP** — мастерская робототехника: железо, прототипы, разработка.
3. **SECTOR 0x03 — RENDER** — пространство 3D-художника: модели, рендеры, скетчи.

Схема подписей: надпись камеры всегда на английском, подпись под ней переключается
вместе с языком сайта.

Вход в комнату (сделано для BLIND SPOT, прототип): клик по монитору → остальные
камеры гаснут в NO SIGNAL, экран камеры растягивается на весь экран с наездом и
размытием, «CONNECTING…», провал в чёрное, комната включается как ЭЛТ. Выход
(«← WATCH ROOM», Esc, «назад» в браузере) — обратно в свой монитор.
- Контент комнаты — отдельный файл `rooms/<id>.html`, грузится во время наезда.
- Адрес комнаты — `#<id>` (например `#blindspot`); прямой вход по ссылке сразу
  открывает логово и комнату без анимации.
- Новая комната = файл в `rooms/` + строка в `ROOMS` (`lair.js`) + `data-room`
  на мониторе. Камеры без комнаты отвечают «ACCESS PENDING».

Дальше: комнаты WORKSHOP и RENDER, затем содержимое комнат (записи).

## Бэкенд: домашний сервер (основной вариант)

Сайт остаётся на GitHub Pages и доступен всем всегда. Расширенные функции
(вход, личные записи, SAI) живут в **приватном репозитории `parallax-backend`**
и работают **на ПК владельца (Windows 10), только пока он запущен** —
`start-lair.bat`, остановка — закрыть окно.

**Сейчас — локальный режим:** бэкенд слушает только `127.0.0.1:8787`, доступен
лишь с этого ПК, из сети недоступен вообще. Терминал сайта подключается к нему
скрытой командой `link` (адрес хранится только в браузере владельца, не в
публичном коде; пока `link` не вызван, сайт никуда не обращается). Индикатор в
шапке терминала: зелёный — link established, красный — offline; `sai` в
POST_CONSOLE видит сервер. Chrome/Edge один раз спрашивают разрешение на доступ
к устройствам — его нужно дать.

Tailscale отклонён: работает как VPN (WireGuard), в РФ нестабилен.

```
Владелец (браузер на ПК) ─► parallaxpov.github.io ─ link ─► http://127.0.0.1:8787 (parallax-backend)
```

- Стек: Python + FastAPI (под SAI), SQLite, настройки в `.env`.
- **В репозитории только код.** Личные данные — в `data/` и `.env` на ПК, в
  `.gitignore`; бэкап отдельно и зашифрованно.
- Изоляция: CORS только для сайта; отдельный пользователь / Docker; SAI —
  доступ к папке проектов только на чтение, без выполнения команд (защита и от
  prompt injection).

Этапы:
1. `/health` + скрипт запуска — готово.
2. `link` в терминале + проверка связи — готово.
3. SAI: разговор с локальной моделью (Ollama, Qwen3.5-9B) — готово. В
   POST_CONSOLE: `sai` — режим разговора (`sai>`, потоковый ответ, `exit`/Esc,
   `reset`), `sai <вопрос>` — один вопрос. Доступа к файлам пока нет.
4. Настоящий `login` (passkey и/или пароль + 2FA — см. «Вход через терминал»).
5. SAI читает проекты (папка только на чтение) — только после `login`.
6. Личные записи и логи.

**SAI: мозги, инструменты, навыки** (главная линия развития SAI):

Характер (из проекта SecureAI): «Ассистент информационной безопасности.
Обладает эмоциями, но они подчинены логике. Заботлива, но осторожна.
Дружелюбна, но бдительна.» Женский род.

| Слой | Что | Статус |
|---|---|---|
| A. Фильтр ввода | длина (2000), явный шум и тройной повтор → ответ в характере без модели; пограничное → модель с пометкой «не ищи смысла» | готово |
| B. Характер и поведение | персонаж + правила по ситуациям (сленг/шутки не буквально, шум не шифр, грубость → граница, prompt injection → отказ) + примеры диалогов | готово, доводить по evals |
| C. Знания | публичные факты + карта сайта — готово; `data/sai_memory.md` — готово; поиск по папке проектов (RAG) — после `login` | частично |
| D. Инструменты | вызов функций моделью: открыть комнату, перейти к разделу, время… — белый список, выполняется в браузере | следующий шаг |
| E. Вывод | потоковый ответ, лимит длины, безопасная разметка (жирный, списки, код) | готово |
| F. Проверки (evals) | `run-evals.bat`: каверзные фразы из `evals/cases.json` → PASS/FAIL, отчёт в `data/evals/` | готово, пополнять |
| G. Безопасность | устойчивость к prompt injection при чтении файлов; личную память — только владельцу | с `login` и RAG |

Идеи дальше: понимание намерения (классификация сообщения перед ответом),
эмоциональное состояние SAI, долгосрочная память разговоров (с разрешения
владельца), выбор модели под задачу (быстрая для болтовни, R1 для разборов).

**Удалённый доступ (позже, без VPN):**
- **VPS-мост без доверия к нему:** ПК сам подключается к VPS по SSH (обратный
  туннель / frp), VPS только пересылает зашифрованный трафик (TLS passthrough),
  HTTPS расшифровывается на ПК — VPS не видит содержимого и ничего не хранит.
- **Белый IP у провайдера** + проброс 443 (+ динамический DNS): ПК доступен
  напрямую; тогда строгая защита периметра — HTTPS, mTLS (клиентские
  сертификаты), лимиты, фаервол, изоляция.
- **ЦОД на работе** — только если разрешает политика компании.
В любом варианте — вход (passkey / 2FA) и mTLS.

**SAI — где считать:** модель («мозг») и данные («память») разделены; бэкенд
обращается к модели по адресу из настроек (`SAI_MODEL_URL`), данные остаются
на ПК. Старт — Ollama на ПК (модели 7–8B ≈ 8 ГБ видеопамяти); перенос
вычислений на сервер с GPU — смена адреса, наружу уходят только нужные под
вопрос фрагменты.

## Отложено (на будущее)

- **Загадка для любопытных.** Цепочка подсказок в духе CTF по «подозрительным»
  деталям сайта (`/0xAC:19F`, `ID: PRX-0x7F2A`, скрытая точка) → вглубь логова.
  Идей по содержанию пока нет — продумать позже.
- **Интерактивный терминал + ИИ SAI.** Сделан терминал сайта (`terminal.js`):
  ярлык снизу слева + клавиша `~`, один движок с профилями:
  - `GUEST_TERMINAL` (портфолио, стиль портфолио): help, whoami, about, projects,
    skills, contacts, lang, fx, date, clear;
  - `POST_CONSOLE` (после взрыва, стиль логова): help, whoami, about, ls,
    open <комната>, contacts, sai, lang, fx, date, clear. Смена профиля в момент
    взрыва — сбой `connection lost` в открытом окне или мигание ярлыка.
  Команды добавлять по мере появления материалов. В будущем у каждого профиля —
  свой контекст SAI и доступ к памяти: гость — публичное о портфолио, пост —
  публичные записи логова, admin — личная память (только на своём хостинге).
- **Секреты и пасхалки.** Скрытые команды (не в help и не в Tab) — список `SECRETS`
  в `terminal.js`; за находку «Congratulations! You found a secret!».
  Первый секрет: подсказка в консоли DevTools → команда в HTML-комментарии
  исходника. Позже добавить: звук сюрприза, конфетти (хук `celebrate()`), новые
  секреты по сайту, счётчик найденного (вместе с «памятью о визите»). В будущем — полноценный хостинг (не только GitHub Pages) и
  подключение SAI из дипломного проекта:
  - для себя: «напомни мне мою цель как специалиста», «что уникального и ценного
    в моих проектах»;
  - для посетителей: «что это за место?» и т. п.
- **Переезд на свой хостинг и полноценная безопасность.** Уйти с GitHub Pages на
  свой сервер, а там уже настоящие решения: серверная аутентификация (логин и
  пароль, 2FA), сессии/токены, разграничение прав на сервере (личное не отдаётся
  без входа), HTTPS и заголовки безопасности (CSP, HSTS), защита от перебора
  (rate limiting), логирование входов, бэкапы, секреты и ключи API (SAI) только на
  сервере. Пока сайт статический, профили терминала и «guest/admin» — только UX,
  не защита.
- **Собственный хостинг: гость и админ.** При переезде с GitHub Pages разделить
  доступ:
  - **guest** — поверхностный слой: то, что видно всем (витрина, открытые части логова);
  - **admin** — вход по логину и паролю к важным и личным материалам (личные записи,
    логи, черновики, SAI в режиме «для себя»).
  Важно: пока сайт на GitHub Pages и репозиторий публичный, всё, что лежит в ветке
  сайта, доступно по прямой ссылке. Личное не класть в репозиторий до появления
  разделения доступа.
- **Вход через терминал (вместо отдельного окна Sign in).** Терминал — только
  интерфейс входа; проверяет всегда сервер. Сейчас есть заглушка: скрытая команда
  `login` (не в help/Tab) спрашивает имя и пароль (пароль — точками, не в истории,
  никуда не отправляется) и отвечает `auth server offline`.
  Схема на своём хостинге:
  ```
  guest@lair:~$ login
  username: parallax
  password: ••••••••••••
  2FA code: 482 913
  access granted · session started
  parallax@lair:~#
  ```
  После входа — профиль ADMIN в терминале (приглашение `#`, свой стиль и команды:
  личные записи, память SAI, `logout`).
  Обязательно:
  1. Пароль никогда не проверяется в JS страницы — только сервер (HTTPS, хеш argon2
     или bcrypt, ответ «да/нет»).
  2. Личное не попадает на страницу до входа — сервер отдаёт закрытое только при
     валидной сессии.
  3. Сессия — cookie `HttpOnly` + `Secure` + `SameSite=Strict` (не localStorage),
     тайм-аут, `logout`; CSRF-токен.
  4. Ввод пароля скрыт, не сохраняется в историю.
  5. Защита от перебора: лимит попыток, задержки, журнал входов; единое сообщение
     `access denied` без подсказок, что именно неверно.
  6. Защита от XSS: экранировать всё, что выводит терминал (ответы сервера тоже), +
     CSP — иначе чужой скрипт уведёт сессию.
  Решить при реализации:
  - **2FA:** TOTP-код прямо в терминале и/или **passkey (WebAuthn)**: `login` →
    отпечаток / Face ID / PIN устройства, без ввода пароля; устойчиво к фишингу
    (рекомендация — passkey как основной, пароль + 2FA как запасной).
  - **Аварийный вход** на случай поломки терминала: скрытая страница `/admin` с
    обычной формой.
  - **Приманка (honeypot)** в духе ИБ: попытки гостей вроде `admin/admin` получают
    правдоподобный отказ и пишутся в журнал — мини-аналитика угроз.
  - Скрытость `login` — бонус, не защита; защищают пункты 1–6.
- **Память о визите.** Запоминать, что логово уже открыто; «вернуться вниз» /
  «закрыть разлом». Отложено, пока в логове нечего запоминать.
